How the page-break distribution algorithm works

Pass 1 — Distribution

Greedy first-fit

  • Sequential, order-preserving — items never reorder to fill gaps
  • Probe page mounted with real CSS for accurate height measurement
  • Available height varies per page (different header/footer heights)
  • Tables split at row boundaries; thead optionally repeated

Break control

data-break attribute

  • auto — split at child boundaries (recursive)
  • avoid — keep together; overflows visibly if too tall
  • clip — keep together; overflow: hidden if too tall
  • Nested avoid/clip disallowed — outer wins, warning emitted

Pass 2 — Rendering

Page assembly

  • Distribution determines final page count first
  • Headers/footers rendered with complete {page, totalPages}
  • Continuation fragments marked with data-hp-continued
  • @page rule + page-break-after for print
